# 37-dashboard-study-record-total-fix

## 背景

学生工作台 `StudentDashboardPage` 里，单题卡片会展示：

- 错次
- 练习次数
- 最近练习记录

但此前前端拉取练习记录时只请求：

- `listStudyRecords(item.id, { limit: 5 })`

然后直接把：

- `(studyRecordMap[item.id] || []).length`

显示成“练习次数”。

这会导致一个明显问题：

- 页面上所谓的“练习次数”其实最多只会显示到 5
- 练习记录一旦超过 5 次，用户看到的数字就不再是真实总次数

这属于 M2 主链路里的统计/字段契约问题，因为它会误导学生对同一题的复练频次判断。

## 本次修复

### 1. 前端不再把“最近列表长度”当总次数

调用 `listStudyRecords()` 后，同时读取接口返回的：

- `items`
- `total`

并分别存储：

- `studyRecordMap` → 最近记录列表，用于渲染明细
- `studyRecordTotalMap` → 真实总次数，用于渲染“练习次数”

### 2. 最近记录展示上限提升

请求上限从 `5` 调整到 `20`，减少高频练习题被过早截断的情况。

### 3. 页面文案补充“只展示最近记录”

当：

- `total > 当前展示条数`

页面会额外提示：

- 仅展示最近 N 条
- 累计 X 次练习

避免把“最近记录列表”误读成“全部历史”。

## 结果

修复后：

- 单题“练习次数”来自后端真实总数
- “最近练习记录”仍保留列表视图，但不再冒充全量历史
- 工作台对“错次 / 练习次数 / 最近练习记录”的语义更清晰

这一步属于 M2 的字段契约收口：
- 总量看 `total`
- 列表看 `items`
- 不再混用分页列表长度与真实累计值
