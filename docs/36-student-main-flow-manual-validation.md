# 36-student-main-flow-manual-validation

## 目的

把学生端当前主链路整理成一份可重复执行的手动验收说明，既用于收尾 M1，也直接服务 M2（错题主链路收口）。

主链路目标：

`登录 → 首页 → 工作台录入/识别 → 错题详情 → 打印 → 线下重做 → 结果回填`

---

## 一、前置条件

1. 后端服务可访问
2. 学生端可正常登录
3. 至少准备一条真实错题数据
4. 最好包含一条带图片的错题，用于验证详情页 / 回填页图片链路

---

## 二、验收步骤

### Step 1：登录态与入口守卫

1. 访问 `/`
2. 未登录时，应自动跳转到 `/student/login`
3. 使用测试环境联调账号登录
4. 登录成功后，应跳转到 `/home`

**通过标准**
- 未登录不能直接进入学生端主页面
- 登录后不会落到错误路由
- 登录页文案明确说明当前是测试环境 / 联调账号入口

---

### Step 2：首页总览

1. 查看首页顶部摘要
2. 核对以下数据是否来自真实统计接口：
   - 累计练习
   - 已掌握 / 总错题
   - 复习中
   - 掌握率
   - 新错题
3. 点击“进入工作台”

**通过标准**
- 首页不再使用最近列表长度冒充总数
- 首页与工作台 / 我的页的统计语义一致
- 能正常跳转到 `/student/dashboard`

---

### Step 3：工作台录入 / 识别 / 保存

1. 在工作台添加一条错题
2. 若有图片，尝试走上传 / 识别 / 手动修正 / 保存
3. 保存后确认该错题出现在工作台列表中

**通过标准**
- 能新增错题
- 识别失败时仍可手动补充后保存
- 保存后列表可见，且状态初始合理（通常为 `new`）

---

### Step 4：错题详情页

1. 从工作台或错题本进入某条错题详情
2. 核对以下信息是否展示：
   - 题目标题
   - 题目内容
   - 学科
   - 错因
   - 备注
3. 如果该错题带图，确认详情页能看到图片

**通过标准**
- 详情页能正确展示真实错题内容
- 带图错题不会在详情页丢图
- 能继续进入打印或结果回填

---

### Step 5：打印重做包

1. 进入 `/print`
2. 勾选若干条非已掌握错题
3. 生成打印包
4. 确认调用真实导出接口并拿到 PDF / 下载地址

**通过标准**
- 打印页展示真实错题列表
- 可以生成真实 PDF
- 生成失败时会提示明确错误

---

### Step 6：结果回填

1. 从详情页进入 `/practice/:id`
2. 对同一条题记录一次：
   - 做对
   - 再错
   - 或跳过
3. 如有备注，填写并提交
4. 如果该错题带图，确认回填页仍能看到图片

**通过标准**
- 能成功调用 `createStudyRecord`
- 回填页不会丢失图片上下文
- 提交后能收到明确成功提示

---

### Step 7：状态回流

1. 提交练习记录后，返回工作台或“我的”页
2. 观察以下数据是否发生合理变化：
   - 累计练习
   - 复习中 / 已掌握 / 新错题
   - 掌握率
3. 如手动调整错题状态，确认工作台和统计页没有明显冲突

**通过标准**
- 学习记录能回流到统计口径
- 工作台、首页、我的页不会出现明显互相打架的统计值

---

## 三、本轮新增修复点（2026-03-18）

### 修复：详情页 / 回填页图片丢失

问题：
- `QuestionDetailPage` 和 `PracticePage` 虽然有图片展示区域
- 但 `mapQuestion()` 之前没有把 `image_url / image_name` 映射到前端对象
- 结果是带图错题进入详情页或回填页时，图片实际不会显示

修复后：
- 详情页可展示错题原图
- 回填页可保留同一题目的图片上下文
- 更符合 M2 “录入 → 错题卡片 → 练习回流”的连续体验

---

## 四、当前结论

- M1：已经接近完成，主要剩余的是手动验收与少量文案收尾
- M2：主链路已经具备基础形态，但还需要继续减少临时兜底和补充状态闭环说明

下一轮建议：
1. 继续审 `StudentDashboardPage` 的联调/临时文案
2. 明确“打印后回填”的产品状态闭环
3. 继续补字段契约与页面说明，减少页面端猜测
