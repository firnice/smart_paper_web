# 41-management-entry-route-exposed

## 背景

在学生端代码中，其实已经存在管理页面：

- `src/pages/management/WorkspacePage.jsx`

而且它接的并不是 mock：

- 用户列表 / 用户创建
- 家长-学生关系绑定
- 学科 / 分类 / 错因维护
- 错题与学习记录维护
- 学生统计概览

对应后端接口也已经存在。

但此前有一个明显问题：

- 页面文件存在
- 接口存在
- **路由不存在**
- 用户根本进不去

这正属于 M3 backlog 里的：

- 找出“功能存在但入口不可达”的页面

## 本次修复

### 1. 正式挂载管理工作台路由

新增：

- `/management`

当前仍复用 `StudentGate` 做基础登录态保护，避免未登录直接进入。

### 2. 在家长入口占位页补一个可见跳转

`/parent/login` 当前还是“家长端暂未开放”的说明页。

本次没有把家长端伪装成可用，而是仅增加一个明确跳转：

- `进入管理工作台`

这样可以：

- 保持家长端仍然是未开放状态
- 同时把已经存在的管理能力暴露出来，便于继续 M3 梳理

### 3. 不把管理入口塞进学生底部导航

管理端入口没有被放进学生主导航，避免污染学生主流程。

## 结果

修复后：

- `WorkspacePage` 不再是“代码里存在、用户永远到不了”的死页面
- M3 可以开始围绕真实入口继续检查：
  - 用户列表
  - 家长学生关系
  - 学生档案/统计
  - 还有哪些管理能力是存在但不可达的

## 当前定位

这一步不是宣布家长端正式可用，而是：

- **把管理工作台从“不可达功能”提升为“可检查的真实入口”**

相当于正式开始触碰 M3。
