# 30-auth-entry-and-routing-hotfix

## 背景

在学生端逐步切换到真实数据后，出现了以下问题：

- 页面提示“请先登录学生端”，但没有明确登录入口
- 主路由未挂载 `/student/login` 与 `/student/dashboard`
- 未登录访问学生页时没有统一重定向
- 导致用户体感为“功能已做，但入口不可用”

## 本次修复

### 1. 路由补齐

- 新增 `StudentLoginPage` 路由：`/student/login`
- 新增 `ParentLoginPage` 路由：`/parent/login`
- 新增学生工作台路由：`/student/dashboard`

### 2. 未登录守卫

新增统一学生登录守卫：

- 未登录访问应用内学生页面时，自动跳转到 `/student/login`
- 根路径 `/` 根据登录态自动重定向：
  - 已登录 → `/student/dashboard`
  - 未登录 → `/student/login`

### 3. 底部导航修正

- 首页入口从 `/` 调整为 `/student/dashboard`
- 避免点击底部“首页”后又回到根路径造成路由歧义

## 经验规则

### 产品规则

1. 任何真实登录能力上线时，必须同时提供明确入口
2. 未登录访问受保护页面时，不允许只显示一条错误提示
3. 必须满足以下二选一：
   - 自动重定向登录页
   - 显示明确且可点击的登录入口

### 工程规则

1. 切换 mock → real data 时，不能只改页面内部数据源，必须同步检查：
   - 路由是否可达
   - 登录入口是否存在
   - 未登录守卫是否完整
   - 底部导航/首页跳转是否一致
2. 新增登录页后，必须检查 `App.jsx` 是否实际挂载了对应路由
3. 用户可见入口未收口前，不得宣称“可用”

## 当前状态

本次修复后，学生端入口链路应调整为：

- 打开 `/` → 自动分流到登录页或学生工作台
- 登录页：`/student/login`
- 登录成功后：`/student/dashboard`
