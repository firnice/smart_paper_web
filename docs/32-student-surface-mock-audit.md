# 32-student-surface-mock-audit

## 目的

对学生端当前用户可见页面做一次“mock / 占位 / 误导性文案”审计，优先找出会让用户误判为“已经正式可用”的部分。

审计时间：2026-03-17

## 本轮结论

### 已收口

#### 1. `/profile` 我的页
- 已从写死 mock 数据切到真实口径
- 见：`31-profile-page-real-data-cutover.md`

#### 2. `/student/login` 登录页文案
- 后端的确存在可用测试账号：`test1 / test2 / test3`
- 因此这里不是“假登录”
- 但之前文案误导成“正式账号体系”，已改成“测试环境联调入口”

#### 3. `/parent/login` 家长入口
- 当前仍是占位页，没有真实登录与查询能力
- 已把文案改成更明确的“暂未开放，请不要当成已可用功能”

## 当前判断

### A. 真实链路页面（可继续迭代）
这些页面已接真实接口或真实页面逻辑，后续重点是体验与口径收口，而不是简单定义为 mock：

- `/home`
- `/student/dashboard`
- `/bank`
- `/question/:id`
- `/practice/:id`
- `/print`
- `/profile`

### B. 已明确转向/防误导页面
- `/upload`
  - 不再走旧 mock 识别流
  - 当前作用是统一跳转到学生工作台

### C. 仍需注意的点

#### 1. 学生登录页仍暴露测试账号
这在联调阶段合理，但不应被包装成正式账号系统。

后续建议：
- 上线前切换为真实账号来源
- 或增加环境标识（开发/测试环境）

#### 2. 家长入口仍只是说明页
虽然已改成明确未开放，但它仍在路由中可访问。

后续建议二选一：
- 要么继续保留，但明确标注“暂未开放”
- 要么在正式上线前直接隐藏入口

#### 3. 页面统计口径仍要统一
虽然 `/profile` 已切真实数据，但“掌握率 / 正确率 / 本周新增 / 本周解决”这些词在不同页面仍需要统一产品定义。
