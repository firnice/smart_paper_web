# 48 - 录入弹窗布局收敛与响应式清理

## 背景

在 47 号文档确认“家长单角色 + 手机 / PC 同功能”之后，录入弹窗仍然是当前最粗糙的区域。

原问题不是单个样式值不对，而是结构层级混乱：

1. 选择来源、整页识别、元素编辑、抠图、预览、表单全部顺序堆叠
2. 同一层里既有主流程操作，也有次要工具动作
3. 手机上滚动过长，PC 上又缺乏稳定的信息分区
4. 按钮和表单样式被全局规则串扰，导致宽度和密度失控

因此本次处理目标是“结构性收敛”，不是单纯调 padding。

## 重构目标

### 目标 1：录入流程更像流程

重新明确四步：

1. 选择来源
2. 整页识别
3. 校对图文
4. 保存入库

要求：

- 顶部必须能一眼看出当前处在哪个阶段
- 每个阶段只承载当前阶段最相关的操作

### 目标 2：主操作与次操作分层

主操作：

- 选图
- 识别
- 载入题目
- 抠图
- 保存

次操作：

- 缩放
- 清除选区
- 背景置白
- 自动去手写
- 元素扫描删除

要求：

- 主操作优先展示
- 次操作集中在对应面板头部或局部工具栏
- 不再把所有按钮堆成同一行

### 目标 3：手机 / PC 一套逻辑，两种布局

手机：

- 单列
- 长流程允许上下滚动
- 右侧信息区折叠到主流程下方

PC：

- 左侧主流程区
- 右侧预览 / 保存区
- 右侧信息区允许 sticky，减少来回滚动

## 页面结构规范

### 新结构

`ComposerModal` 调整为：

1. 顶部 Hero 区
2. 步骤条
3. 双栏主体

主体布局：

- 左栏：来源、整页识别、抠图、元素编辑
- 右栏：卡片预览、保存表单

这样处理后：

- 用户先处理“输入与识别”
- 再处理“保存与结果”
- 主流程和结果区不再互相打断

### 右栏职责

右栏不承接识别工具，只承接：

1. 当前卡片预览
2. 保存字段编辑
3. 最终保存动作

约束：

- 右栏不放 OCR 列表
- 右栏不放整页预览
- 右栏不放图像清理工具

## 样式规范

### 1. 按钮宽度收口

历史问题：

- `btn-primary / btn-secondary` 继承了全局 `width: 100%`
- 录入弹窗内的操作按钮显得过宽、过重、过乱

本次规范：

- 在录入弹窗内重置按钮宽度为 `auto`
- 只有移动端底部保存区才允许按钮满宽

### 2. 面板视觉统一

录入区所有主要模块统一成 `student-panel`：

- 圆角
- 边框
- 渐变浅底
- 一致的标题、说明、动作区

目的：

- 减少局部样式风格漂移
- 让录入流程看起来像同一系统下的面板，而不是多段拼接

### 3. 预览区稳定

整页图和 OCR 图示必须使用统一容器：

- 带边框
- 带最大高度
- 容器内部滚动

这样可以避免：

- 整页图片直接把弹窗撑爆
- PC 下图片过高导致表单被挤出视口

### 4. 移动端收口

手机下要求：

- 双栏降为单栏
- 步骤条改为单列
- 面板头部动作区竖排或左对齐
- 保存按钮恢复满宽

## 后续建议

这次主要解决的是“布局混乱”和“信息层级混乱”，还没完全解决以下问题：

1. OCR 结果卡片仍然信息较多，后续可继续压缩摘要与图示关系
2. 元素扫描编辑仍偏技术向，后续可继续简化文案
3. 录入表单字段还可以再按“必填 / 可选”分层
4. 如果后续要更强的桌面体验，可以把“预览卡片”和“表单”做成可切换标签而不是同时展示
