# 47 - 家长单角色双端统一产品与响应式规范

## 背景

当前产品真实痛点已经收敛，不再是“学生在线做题”，而是：

1. 家长能够高效录入纸面错题
2. 家长能够在较大屏幕上整理、筛选和打印
3. 录入、整理、打印、回填结果共用同一份错题数据

因此产品策略从“学生端 / 家长端 / 管理端混合”收敛为：

- 只保留一个对外角色：`parent`
- 手机和 PC 都提供同一套核心功能
- 不再按角色拆产品，而是按设备场景调整默认入口和布局

本轮前端改造已按该方向落地到路由和页面壳层。

## 核心决策

### 1. 角色收敛

对外仅保留一个使用角色：

- `parent`

不再继续扩张：

- `student`
- `teacher`

说明：

- 当前业务核心不是让孩子在设备上完成练习
- “学生端在线练习”不再作为产品主入口
- 线下重做 + 家长回填结果，才是当前更真实的主链路

### 2. 产品统一

不是做两套产品，而是做一个产品，两种设备形态：

- 手机：录入更方便
- PC：整理、排版、打印更方便

约束：

- 两端功能保持一致
- 两端数据完全一致
- 两端接口完全一致
- 两端只允许“默认入口、布局和信息密度”不同

### 3. 业务优先级

P0 主链路：

1. 拍照 / 上传
2. OCR / 切题 / 裁剪
3. 保存为错题
4. 错题筛选与整理
5. 生成打印重做包
6. 线下重做后回填结果

P1 增强链路：

1. 趋势分析
2. 高频错题提醒
3. 学科分布与掌握趋势

P2 附加能力：

1. 举一反三
2. AI 解析
3. 更复杂的学习分析

原则：

- AI 能力不能挡在录入主链路前面
- 打印能力必须是与录入并列的一等功能

## 产品信息架构

### 顶层模块

统一保留五个真实模块：

1. `capture` 录入中心
2. `workspace` 错题本
3. `print` 打印重做包
4. `analysis` 学习分析
5. `profile` 家庭工作台

### 模块定位

#### capture

用于：

- 手机拍照录入
- 相册选图
- 整页试卷上传
- OCR 识别
- 题块裁剪
- 识别结果校对

定位：

- 手机默认入口
- PC 可访问，但不作为主要工作区

#### workspace

用于：

- 浏览错题列表
- 按学科 / 学期 / 状态 / 关键词筛选
- 编辑错题信息
- 标记掌握状态
- 收藏、删除、继续练习

定位：

- 双端核心工作区
- PC 默认主入口

#### print

用于：

- 选题生成打印包
- 切换打印强度模式
- 控制是否隐藏答案
- 导出 PDF / 打开导出结果
- 导出后进入结果回填

定位：

- 双端可用
- PC 体验优先

#### analysis

用于：

- 查看错题总量
- 查看学科分布
- 查看掌握趋势
- 查看高频错题提醒

定位：

- 双端可用
- 适合用来决定下一批打印内容

#### profile

用于：

- 展示当前孩子信息
- 展示账号相关能力
- 承接“家庭工作台”语义

定位：

- 双端可用
- 不是“学生我的页面”，而是家庭视角入口

## 路由规范

### 新主路由

```txt
/login
/capture
/workspace
/print
/analysis
/profile
/question/:id
/practice/:id
```

### 旧路由兼容策略

旧路径保留重定向，不直接删除：

- `/student/login` -> `/login`
- `/parent/login` -> `/login`
- `/student/dashboard` -> `/workspace`
- `/upload` -> `/capture`
- `/home` -> `/analysis`
- `/mine` -> `/analysis`
- `/management` -> `/workspace`

原则：

- 老链接不立刻打断
- 新产品心智全部收口到统一主路由

## 响应式规范

## 设计原则

响应式不是简单缩放，而是：

- 小屏保留当前任务
- 大屏增加上下文和辅助操作

因此必须遵守：

1. 功能一致
2. 信息密度不同
3. 操作路径不同
4. 状态和数据一致

### 手机端规范

手机端默认目标：

- 快速拍照
- 快速上传
- 快速保存

规范：

1. 默认首页可落到 `capture`
2. 采用单栏布局
3. 主 CTA 固定明显，优先触发录入
4. 列表项展示摘要，不强行展示全部上下文
5. 长流程采用分步骤模态或全屏面板

适合手机的动作：

- 拍照
- 选图
- 框选
- 快速确认
- 轻量查看错题列表

### PC 端规范

PC 端默认目标：

- 看整页
- 修 OCR
- 批量筛选
- 打印排版

规范：

1. 默认首页可落到 `workspace`
2. 支持双栏或多栏布局
3. 页面右侧允许出现“摘要 / 下一步 / 快捷动作”侧栏
4. 打印页必须支持“选题区 + 设置区”并列
5. 顶部允许出现页面说明和跨设备提示

适合 PC 的动作：

- 批量看题
- 大图检查
- 多条件筛选
- 设置打印模式
- 打开 PDF / 直接打印

### 布局约束

通用约束：

1. 手机和 PC 不允许出现不同的数据定义
2. 手机和 PC 不允许出现某个核心功能只存在一端
3. 不允许为了“完全复用页面结构”牺牲大屏效率
4. 不允许为了“大屏做得更像后台”破坏移动录入效率

推荐实现方式：

- 共享业务页
- 页面内按断点改变布局
- 少量壳层组件区分移动 / 桌面结构

不推荐：

- 整体复制两套页面
- 手机一套路由，PC 一套路由，数据却相同
- 同一功能因设备不同出现不同字段和不同流程定义

## 页面级规范

### AppFrameLayout

壳层分两种形态：

- 手机：底部导航 + 中央录入按钮
- PC：左侧导航 + 顶部页面说明

要求：

1. 手机底部始终保留录入入口
2. PC 侧栏始终提供录入、错题本、打印、分析、我的
3. 当前孩子基础信息可在 PC 侧栏底部展示

### WorkspacePage

移动端：

- 统计条 + 错题列表
- 顶部保留新增按钮

桌面端：

- 左侧主列表
- 右侧“当前摘要 / 下一步 / 跨设备建议”辅助区

### PrintPage

移动端：

- 单列流程可继续使用

桌面端：

- 左侧题目选择区
- 右侧打印模式、设置、导出状态区

这是当前最重要的大屏优化页面。

### Analysis / Profile

要求：

- 从“学生视角”改为“家庭 / 孩子视角”
- 保留真实数据统计，不再强调学生端独立身份

## 风险与后续

### 当前风险

1. 后端登录接口仍是 `student-login` 语义
2. session 工具仍使用 `studentSession` 命名
3. 部分历史页面和文案仍残留学生口径，但已不在主路由中承接

### 下一步建议

1. 后端认证与 session 命名统一为 `parent` 或通用 `user`
2. 将 `analysis` 页面从统计卡片继续扩展为“高频错题决策页”
3. 为 `capture` 增加明确的“手机优先 / PC 也可上传整页”引导
4. 把打印后的回填链路整理成更明确的闭环状态流
